Vibe_Cowork_Thinking은 Codex와 Gemini 같은 AI 도구를 개별 채팅이 아니라 프로젝트 룸과 실행 이력 중심으로 관리하려는 실험입니다. Runner가 Windows Host의 실제 명령을 맡고, Orchestrator가 웹 UI와 작업 흐름을 담당하며, conversation·runs·journals를 나눠 저장해 재현 가능한 협업 워크플로를 만드는 데 집중합니다.

AI 협업 도구를 실제 운영 흐름으로 재해석한 저장소

단순 채팅 인터페이스 소개가 아니라, 프로젝트와 로그, 실행 권한, Git 흐름을 어떻게 묶을지에 대한 실험 기록입니다.

01

Runner와 Orchestrator를 분리한 구조

실제 명령 실행과 웹 기반 워크플로 관리를 나눠 책임 경계를 명확히 했습니다.

02

프로젝트 룸별 로그 축적

conversation, runs, journals를 분리해 프로젝트 단위 추적과 회고가 가능하도록 설계했습니다.

03

Git 흐름까지 연결되는 Host Runner API

상태 조회에서 commit, push까지 이어지는 guarded flow 실험을 통해 실제 협업 환경을 닮게 만들고 있습니다.

Workflow

이 저장소를 이해하는 가장 쉬운 흐름

README와 TODO, 백테스트 리포트를 함께 묶어 프로젝트 의도와 현재 상태가 동시에 보이도록 구성했습니다.

1. Runner를 먼저 실행

Windows Host에서 codex, gemini, git 명령을 제어할 수 있는 기반을 준비합니다.

2. Orchestrator와 Web UI 기동

프로젝트 룸을 만들고 작업 흐름과 로그를 브라우저에서 관리할 수 있게 합니다.

3. Backtest와 TODO로 현재 성숙도 확인

무엇이 통과했고 무엇이 아직 과제인지 문서와 결과 파일로 바로 이어서 확인할 수 있습니다.

FAQ

자주 묻는 질문

Vibe_Cowork_Thinking은 무엇을 실험하나요?

AI 코딩 도구를 프로젝트 룸과 실행 워크플로 단위로 관리하는 방식을 실험합니다.

Runner는 어떤 역할을 하나요?

Windows Host에서 codex, gemini, git 명령을 제어하고 작업 상태를 반환합니다.

왜 로그 구조가 중요한가요?

conversation, runs, journals를 분리 저장해 프로젝트 단위 추적과 재현을 가능하게 하기 때문입니다.
